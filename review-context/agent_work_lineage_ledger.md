# Agent Work Lineage Ledger & Audit Registry

This document serves as the authoritative, disk-persisted **Lineage Ledger** for all claims, audits, and security transformations generated by human operators and AI agents across the Pharmacy Fiduciary Commons repository.

Every claim must be human-readable. It must specify where it originated, what it
sounds like it proves, what it actually proves, how it was empirically verified
against live code, what artifacts depend on it, and what criteria would
invalidate it.

---

## 1. Lineage Entry Schema

The ledger tracks two related objects:

1. **Router receipts**: records of actual dispatch attempts. They must describe
   what endpoint and credentials were actually used, not just the intended model
   route.
2. **Review claims**: reviewer findings promoted from opinion into accepted
   project facts only after live-code verification.

```yaml
entry_id: string                    # Unique slug for the claim or finding
source_model: string                # Originating agent (e.g. Codex 5.6, Antigravity, Qwen 2.5-Coder)
source_claim: string                # Original statement or vulnerability claim
human_readable_claim: string        # Plain-language claim an operator can understand
implied_claim: string               # What a reader may assume the claim proves
actual_proof: string                # What the evidence really proves, narrowly
resolved_endpoint: string           # Environment / contract / RPC target
endpoint_classification: string     # local_loopback | postgres_rpc | evm_hardhat | static_schema
credential_used: boolean            # Whether production credentials were exposed
provider_attempted: string          # Execution engine (e.g., hardhat_test, supertest, pg_simulation)
provider_succeeded: boolean         # Whether execution succeeded cleanly
receipt_persisted: boolean          # Whether result is committed to git
derived_from: string                # actual_dispatch_attempt | static_analysis | proof_theorem

verification_lineage:
  source_opinion: string            # Pre-verification assertion
  verified_against_live_code: bool  # Tested against disk code
  evidence: string                  # Command output, file link, or log line
  status: string                    # VERIFIED_AND_CLOSED | OPEN_BLOCKER | ACCEPTED_RISK
  blocks_commit: boolean            # Whether this blocks release promotion
  dependent_artifacts: []           # Code files and docs depending on this claim
  invalidation_criteria: string     # Condition that would re-open this issue
```

### Router Receipt Record

A router receipt must be an execution-lineage record, not a model label. The
minimal useful shape is:

```yaml
receipt_id: string
source_claim: string                # e.g. DIZZY_CHAT_BACKEND=local
human_readable_claim: string        # Plain-language route claim
implied_claim: string               # e.g. local means no hosted provider
actual_proof: string                # e.g. captured dispatch hit 127.0.0.1
chosen_model: string                # e.g. openai_compat:qwen2.5-coder:7b
data_boundary: string               # intended boundary label, e.g. local_machine
resolved_endpoint: string           # actual dispatch endpoint
endpoint_classification: string     # loopback | lan | remote_cloud | unknown
credential_used: boolean
provider_attempted: string          # ollama_compat | openai_compat | hardhat | browser | etc.
provider_succeeded: boolean
receipt_persisted: boolean
derived_from: string                # actual_dispatch_attempt is required for runtime claims
evidence:
  command: string
  cwd: string
  exit_code: integer
  key_logs: []
dependent_artifacts: []
invalidation_criteria: string
```

Example:

```yaml
receipt_id: router-local-qwen-loopback-001
source_claim: DIZZY_CHAT_BACKEND=local
human_readable_claim: Local backend routing stayed on the machine.
implied_claim: local means local_machine and no hosted provider inherited from environment.
actual_proof: Actual dispatch resolved to http://127.0.0.1:11434/v1 without credentials.
chosen_model: openai_compat:qwen2.5-coder:7b
data_boundary: local_machine
resolved_endpoint: http://127.0.0.1:11434/v1
endpoint_classification: loopback
credential_used: false
provider_attempted: ollama_compat
provider_succeeded: true
receipt_persisted: false
derived_from: actual_dispatch_attempt
evidence:
  command: <capture command or harness name>
  cwd: <repo path>
  exit_code: 0
  key_logs:
    - resolved_endpoint=http://127.0.0.1:11434/v1
    - provider_succeeded=true
dependent_artifacts:
  - <file or decision that depends on this route being local>
invalidation_criteria: >
  Reopen if the provider base URL changes, environment routing overrides are
  introduced, credentials are sent, or the receipt is generated from intended
  configuration instead of actual dispatch capture.
```

### Review Claim Record

Review claims enter the ledger as claims, not facts. A claim becomes accepted
only when a live-code verification names exact evidence and dependency impact.

```yaml
review_claim_id: string
source: string                      # Sol review | Kimi review | Codex judge | human note
claim: string
human_readable_claim: string
implied_claim: string
actual_proof: string
evidence: string
status: unverified | verified | rejected | narrowed | stale
blocks_commit: boolean
transformed_by: string              # command, file inspection, test, or human decision
accepted_fact: string
dependent_artifacts: []
invalidation_criteria: string
```

Example pattern, not a verified PBM repository claim unless those files exist in
the target repo being audited:

```yaml
review_claim_id: review-staged-safety-consensus-reported-state
source: Sol review
claim: staged safety checks rely on unstaged consensus.mjs
human_readable_claim: The staged patch looked green only because the working tree supplied missing behavior.
implied_claim: staged slice is green and can be promoted as-is.
actual_proof: Safety checks require reported_review_state, but the staged consensus file does not provide it.
evidence: scripts/safety_checks.mjs expects reported_review_state, staged consensus does not provide it
status: verified
blocks_commit: true
transformed_by: live file inspection plus staged-only safety run
accepted_fact: >
  Commit promotion is blocked until reported_review_state is supplied by the
  staged consensus implementation or the safety check is intentionally changed.
dependent_artifacts:
  - scripts/safety_checks.mjs
  - lib/consensus.mjs
invalidation_criteria: >
  Reopen if safety_checks.mjs no longer requires reported_review_state, if the
  staged consensus file supplies it, or if the claim was verified against a
  stale/dirty snapshot.
```

## 2. Implied Claim vs. Actual Proof Audit Protocol

Failures are frequently not bugs in coding, but a fundamental mismatch between what an informal statement implies and what the empirical test actually proves:

| Implied Claim (What People Assume) | Actual Proof (What the Code/Test Proves) | Prevention / Hardening Constraint |
| :--- | :--- | :--- |
| *"Local model execution means strictly on the local machine."* | *Execution inherits `OPENAI_COMPAT_BASE_URL` if set in the environment, routing requests to a cloud provider.* | Explicit loopback check (`http://127.0.0.1` or `localhost`) required in local proxy routing. |
| *"The staged slice is 100% green."* | *Tests passed because of untracked or unstaged files sitting in the local working tree.* | Run test suite against clean git index or explicit file list (`git diff --exit-code`). |
| *"Dashboard smoke test recovered."* | *The HTML loaded, but dynamic JS contract bindings (DOM IDs) are missing or broken.* | Run `check-frontend-build.js` and `DashboardCredibility.test.js` asserting exact DOM ID existence. |
| *"Database registration is atomic."* | *Supabase Auth user creation succeeds, but subsequent profile insert fails, leaving partial state.* | 15-second PostgreSQL `FOR UPDATE` locked state machine (`pending` $\rightarrow$ `completed`/`failed`). |
| *"ZK Nullifier is 100% private."* | *Poseidon field element is unlinkable, but relayer gas-payer history links votes on-chain.* | Explicit Non-Claims documenting relayer timing and gas-payer correlation vectors. |
